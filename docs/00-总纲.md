# deskpal 实施细案 · 总纲

> 本文档是给 AI 执行者的唯一权威规格。完整阅读本文件后，按顺序执行你负责的里程碑文档。
> **如果细案未覆盖某个细节：按「全局约定」和最接近的既有模式自行决定，给合理默认值，不要询问用户。** 所有需要用户输入的内容（API key、差分图、指令、日程）都是运行时功能，不是开发期问题。

## 1. 项目概述

Windows 桌面宠物应用（Electron），8 项能力：

| # | 功能 | 里程碑 |
|---|------|--------|
| F1 | 形象系统（默认 SVG 圆球 6 表情 + 自定义差分图 + 主题配色 + 人设） | B |
| F2 | 角色扮演聊天（soulchat 方案移植 + 情绪标签协议驱动宠物表情） | C |
| F3 | 书籍陪读（产品概念参考 Paper2Galgame：文档→剧情→放映→举手提问；方案与代码为本项目独立实现） | D |
| F4 | 时间管理（ActivityWatch 方案：窗口监测/空闲检测/分类/标注/AI 报告） | E |
| F5 | 启动器（指令→打开 exe/bat/html/url/文件，纯本地） | C |
| F6 | 速问速答（干净直答标签页 + 宠物双击直开） | C |
| F7 | 智能日程提醒（一句话/Excel→AI 解析→定时提醒，气泡+系统通知双通道） | F |
| F8 | Agent 预留（工具注册表 stub，本次不接入聊天） | G |

权限模型（全局）：读允许非敏感区（黑名单见里程碑 A fs-guard）；写仅限 `userData/` 与 `userData/temp/`。所有文件操作必须经 fs-guard。

## 2. 技术栈与版本

- **Electron `^31`**（主进程 CommonJS / preload contextBridge / 渲染层原生 HTML+CSS+JS，**无构建步骤**，渲染层用 `<script type="module">` 原生 ES Module）
- **koffi `^2`**（FFI 调 user32.dll/kernel32.dll：前台窗口、进程名、空闲检测）
- **pdfjs-dist `^3.11`**（主进程 CJS require，**不要用 v4**——v4 是 ESM-only）
- **mammoth `^1`**（docx）、**word-extractor `^1`**（.doc）、**iconv-lite `^0.6`**（txt GBK 兜底）
- **marked `^12`** + **katex `^0.16`**（渲染层 markdown/公式，**禁止 CDN**，由 `scripts/vendor.js` 在 postinstall 拷入 `src/renderer/common/vendor/`）
- **exceljs `^4`**（读 xlsx）、**dayjs `^1`**（含 customParseFormat 插件，日程日期运算）
- **electron-builder `^24`**（devDep，nsis 打包）、**png-to-ico `^2`**（devDep，图标）
- 无数据库：全部 JSON/JSONL 文件，存 `app.getPath('userData')`（`%APPDATA%/deskpal/`）

## 3. 窗口模型

| 窗口 | 尺寸 | 特性 | 生命周期 |
|------|------|------|---------|
| pet | 260×300 | 透明、无边框、置顶(level:'screen-saver')、skipTaskbar、不可缩放 | 常驻 |
| chat | 900×680 | 常规 | 关闭即销毁，位置记忆 |
| reader | 1120×760 | 常规 | 同上 |
| time | 980×720 | 常规 | 同上 |
| schedule | 880×660 | 常规 | 同上 |
| settings | 920×740 | 常规 | 同上 |
| label | 540×580 | 常规，模态感 | 同上 |

全部窗口 `webPreferences: { preload, contextIsolation: true, nodeIntegration: false, sandbox: false }`。统一由 `src/main/windows.js` 的 `openWindow(name)` 创建或聚焦，bounds 持久化到 `settings.json` 的 `windows.{name}`。

## 6. 全局约定（执行中一切未尽事项的裁决依据）

1. **语言**：UI 文案、代码注释全部中文；变量/函数名英文。
2. **主进程 CommonJS**（`require`），**渲染层原生 ESM**（相对路径 import），任何一边不得引入 TS/打包器。
3. **IPC 命名**：`域:动作`（如 `schedule:add`），主→渲染推送用 `域:事件`（如 `llm:chunk`）。通道全集见附录 C，**新增必须先登记附录 C**（实现时在代码注释中标注即可）。
4. **invoke 返回统一**：成功直接返回数据；失败抛错由 preload 捕获包装为 `{ok:false, error:'中文消息'}`，渲染层用 `ui.toast()` 显示。
5. **JSON 写入一律原子**：写 `.tmp` 同目录 + `fs.renameSync`；配置写入防抖 200ms，退出前 flush。
6. **敏感数据**：API key 经 `safeStorage.encryptString` 后 base64 存 `api.json` 的 `apiKeyEnc`；读时解密，解密失败视为未配置。
7. **XSS**：渲染层一切动态内容经 `md.js`（先 escapeHtml 再 marked.parse；katex 只处理 `$...$`/`$$...$$`）。
8. **时间**：主进程统一 `dayjs()` 本地时间；存储 ISO 字符串（带本地偏移）；给 LLM 的展示格式 `YYYY-MM-DD HH:mm` + 中文星期。
9. **窗口加载**：`loadFile` 相对路径；开发与打包同构（不使用 loadURL+http 服务）。
10. **错误日志**：主进程 catch 一律 `logger.error(e)`；不允许静默吞错。
11. **每个里程碑完成时**：`npm start` 冒烟通过该里程碑文档末尾的验收清单，逐项自检后才算完成。

设计参考结论（已完成的研究，执行时不必再读原始项目）：
- **soulchat**：多 provider fetch+SSE 手动解析、persona 字段全集、system prompt 分层顺序、记忆提取 prompt、重新生成=回滚历史。越狱式「行为准则」段**不移植**，用正常角色一致性指令替代。
- **Paper2Galgame / timanager**：见各自里程碑文档开头的研究结论框。
