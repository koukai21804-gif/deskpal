# deskpal 桌面宠物 — 实施计划（定稿）

> 本文件为用户已确认的完整实施计划（2026-09-16 确认：整体方案 ✓、提醒双通道 ✓、聊天日程联动 ✓）。
> 执行级规格见 `docs/00-总纲.md` 起的细案系列，细案与本文冲突时以细案为准。

全新 Electron 项目（deskpal 目录当前仅含 docs 与 .zcode），实现全部 8 项功能（7 个功能 + 1 个 Agent 预留）。技术底座与 Paper2Galgame 同栈（Electron），渲染层沿用用户熟悉的 soulchat 无构建、模块化原生 JS 风格（不用 React/Vite，降低维护成本）。

## 技术选型
- **Electron ^31**（主进程 Node.js CommonJS + 渲染层原生 HTML/CSS/JS 原生 ESM，无构建步骤）
- **koffi**（FFI）调 user32.dll：`GetForegroundWindow/GetWindowTextW/QueryFullProcessImageNameW`（窗口监测）、`GetLastInputInfo`（空闲检测）——与 ActivityWatch 完全相同的 API 轮询方案，无全局钩子、无原生编译
- **pdfjs-dist 3.x**（主进程 CJS，PDF 文本层逐页提取）、**mammoth**（docx）、**word-extractor**（旧版 .doc）、**iconv-lite**（txt GBK 兜底）、**marked** + **katex**（渲染层 markdown/公式，vendor 本地化禁 CDN）
- **exceljs**（日程 Excel 项目表解析）、**dayjs**（日程日期运算）
- **无数据库**：活动事件按天 JSONL + 心跳合并（ActivityWatch 模式）；配置/存档/人设全部 JSON 文件存 `app.getPath('userData')`，API key 经 safeStorage 加密
- **electron-builder** 打包 nsis exe + 图标（png-to-ico 生成）

## 功能实现方案（对应 8 条需求）

**F1 形象系统**：默认形象为原创自绘 SVG 绿色圆球（Haro 风格参考、不使用原图：径向渐变绿球 #8DC63F、深绿分割线、红色竖椭圆眼 #B03A3A、黑色细线嘴，规格见细案 B）；程序化生成 平常/开心/惊讶/愤怒/思考/悲伤 6 种表情差分 + 眨眼/呼吸/弹跳动画；设置页 6 槽位上传自定义差分图（png/jpg/webp/gif ≤8MB，复制入 `sprites/`，`sprites.json` 映射）；按钮配色 = CSS 变量主题（5 预设+取色器+深浅模式，全窗口即时同步）；Agent 角色扮演属性 = persona.json，字段沿用 soulchat（name/tagline/appearance/personality/speechStyle/catchphrases/background/emotionalPatterns/taboos/thinkingLogic/customPrompt/language + user 对话对象）。

**F2 角色扮演**（soulchat 方案移植）：分层 system prompt（人设→对话对象→当前时间→长期记忆→交互规则+**标签协议**：每条回复末尾附 `[情绪:XX]`，解析剥离后广播驱动宠物表情——补上 soulchat 没有的情绪通道；soulchat 的越狱式"行为准则"段不移植，改写为正常角色一致性指令）；SSE 流式渲染、停止保留半截、重新生成回滚（soulchat 同款语义）；每 10 条用户消息后台低温(0.3)提取记忆（soulchat 原版 prompt，JSON 数组 type/content/importance 1-5，失败正则兜底，上限 50 条淘汰最低重要性）。

**F3 书籍陪读**（产品概念参考 Paper2Galgame；以下方案、数据 schema 与代码均为本项目独立设计实现）：
- 解析：txt/md 直读（utf8 失败自动 GBK 兜底）；pdf 逐页提取+页标记+每页字符数统计检测扫描版（扫描版提示改传文本版，OCR 留接口不实现）；docx 用 mammoth；doc 用 word-extractor；清洗去 URL/DOI/尾随参考文献；上限 30 万字符
- 两阶段生成：①"结构分析师"人格出大纲（3-6 节：title/summary/keyPoints/每节情绪/测验意图，无对话）②"宠物本人"人格逐节产出紧凑 flow：`{t:"d",e:"happy",x:"台词",bb:"黑板markdown"}` 与 `{t:"q",q,o:[3选项],c:正确下标,f:[3反馈]}`，本地编译为帧序列，严格 schema 校验+失败带错误重生成
- 放映：宠物窗表情同步切换 + 阅读窗对话框（打字机/自动播放/历史回看）+ 黑板栏（marked+KaTeX）+ 3 选 1 测验（分支反馈后汇合）
- **举手提问**：侧信道 prompt（人设+按问题相关度选取的原文块 [C1] 引用+当前剧情上下文），明确"不改动剧本状态"，问答记入存档不推进帧
- 存档：每本书 JSON（outline/frames/qa/cursor），可续读

**F4 时间管理**（ActivityWatch 方案复刻）：主进程 1s 轮询前台窗口（exe 名/完整路径/窗口标题）、5s 轮询 `GetLastInputInfo`（180s 判空闲，均可配）；心跳合并成会话写按天 JSONL；分类 = 正则规则匹配 exe+标题（最长正则优先，内置常见应用预设+系统应用忽略表）+用户自定义类别；**空闲归来**若当天存在未分类应用 → 宠物气泡问"今天开启的部分应用我不明白是什么类型的，你可以帮我标注一下吗？" → 标注窗口（列出未知应用名/标题/时长 → 选 工作/学习/娱乐/社交/其他/自定义，保存即生成用户规则）；统计页（今日/本周、按应用/类别排行、24 小时分布，纯 CSS 无图表库）；**AI 报告**按钮 → 聚合 JSON + 人设口吻 → LLM 生成 markdown 报告。

**F5 启动器**：`commands.json` 存 {指令词, 路径, 参数}；聊天输入先本地匹配"打开X/启动X"再走 LLM（纯本地零 API）；exe→spawn detached、bat→cmd /c、html/url→shell.openExternal、其他→shell.openPath；右键菜单快捷子菜单。

**F6 速问速答**：聊天窗"快问"标签页（干净 system prompt 直答，不带角色扮演剧情，保持宠物口吻轻人设，注入当前时间）+ 宠物双击直开聊天窗。

**F7 智能日程提醒（新增，需接 API，无 API 时手动表单兜底）**：
- **输入三通道**：①日程页一句话速添（LLM 解析，prompt 注入当前时间+星期，输出绝对时间；本地校验：合法/非过去/≤1年；模糊时间返回追问）②聊天标签协议联动（LLM 识别明确日程意图时回复附 `[日程:{json}]`，渲染层剥离弹确认条，确认入库，失败静默）③Excel 项目表上传（exceljs 读取→LLM 拆解任务列表（相对时间换算绝对时间）→可编辑预览表→批量导入，同表任务共 groupId）+ 手动表单兜底
- **提醒计划**：类型化预设入库时物化为具体触发时间戳——事件：提前60min+开始时刻；任务开始：提前5min+开始时刻；deadline：提前120min+截止时刻；可增删改
- **调度与触达**：主进程 30s tick；触发**先持久化再广播**（防崩溃重发）；**双通道**＝宠物气泡提醒卡（惊讶表情+知道了/稍后10分钟/已完成/查看）+ Windows 系统通知（可点击跳转日程页）+ 可选提示音；snooze 支持多次；启动补报 24h 内错过的提醒（汇总气泡+日程页红条），更早静默标 missed
- **视图/存储**：速添栏+导入区+今起7天条+分组列表（今天/明天/本周/更晚/已完成）；`schedule/events.json` 单文件原子写

**F8 Agent 预留**：`agent/tools.js` 工具注册表（name/desc/params/permission/enabled/handler），本次只注册只读工具 read_file/list_dir（经 fs-guard）且**不接入聊天**；write_file/edit 工具以 enabled:false 注册（handler 前置 fs-guard，白名单 userData+temp）；后续开发只需启用+接 loop。

**权限模型**：全部文件操作经 `fs-guard.js`——读：允许非敏感区（黑名单：Microsoft/Protect、Crypto、NTUSER.DAT、浏览器 Login Data/Cookies/Web Data、Firefox logins.json/key4.db、.kdbx、SSH 私钥、钱包文件）；写：仅 `userData/` 与 `userData/temp/` 白名单。
