# 里程碑 F · 智能日程提醒

前置：C（依赖 llm.js 的 genericCompletion、聊天确认条接线）。**用户已确认：气泡 + 系统通知双通道；聊天日程标签联动启用。**

## F1. 数据模型（`schedule/events.json`，schema 详见附录 B）

```js
// event
{ id: "evt_20260916140522_x7k3",      // evt_ + 时间戳 + 4位随机
  kind: "event" | "task",              // 日历事件 / 工作任务
  title: "和女朋友约会", notes: "",
  start:  "2026-09-17T18:00:00+08:00", // dayjs().format() 本地 ISO；task 可为 null（只有 deadline 时）
  end:    null | ISO,                   // start+durationMin 物化
  deadline: null | ISO,
  reminders: [                          // 入库时由预设物化出的具体触发点
    { id: "r1", at: ISO, label: "提前60分钟", kind: "lead|atstart|atdeadline",
      status: "pending|fired|missed",   // snooze 用 snoozedTo 表达，不占 status
      firedAt: null, snoozedTo: null, snoozeCount: 0 }
  ],
  status: "pending|done|cancelled", source: "nl|chat|excel|manual",
  groupId: null | "grp_...",            // excel 批量导入共享
  createdAt: ISO, updatedAt: ISO, doneAt: null }

// 文件根：{ version: 1, events: [...] }
```

**提醒物化规则**（读 `settings.schedule`，默认 60/5/120 分钟）：

| remindPreset | 生成 reminders |
|---|---|
| event | [start-60min「提前60分钟」, start「开始」] |
| start | [start-5min「提前5分钟」, start「开始」] |
| deadline | [deadline-120min「提前120分钟」, deadline「截止」] |
| none | []（仅在列表中展示，不提醒；也可手动加提醒） |

编辑事件的 start/deadline/preset → **重建未触发的 reminders**（已 fired 的保留历史）；done/cancelled → 剩余 pending 置 cancelled 同类状态（直接删除亦可，列表不再显示）。

## F2. 自然语言解析（services/schedule/parser.js）

`parseNL(text) → { understood, draft?|null, question?|null }`

- prompt（`prompts.scheduleParse`）全文：

```
你是日程解析器。只输出一个 JSON 对象，不要有任何其他文字。
当前时间：{nowText()}

用户说：「{text}」

输出：
{"understood": true,
 "kind": "event 或 task",
 "title": "简短标题(≤12字,保留用户原意但去掉时间信息)",
 "start": "YYYY-MM-DD HH:mm",
 "durationMin": 数字或null,
 "deadline": "YYYY-MM-DD HH:mm 或 null",
 "remindPreset": "event/start/deadline/none",
 "question": "需要追问时写追问内容,否则为null"}

规则：
- 相对时间(今天/明天/后天/下周三/晚上6点/半小时后)一律换算为绝对时间，24小时制
- 约会/会议/聚会/外出/看病等日历安排 kind=event；作业/赶工/交付/复习等有开始或截止的任务 kind=task
- remindPreset：event→"event"；task 有明确开始时间→"start"；task 主要是截止时间→"deadline"；无时间→"none"
- 只说了大致时间(如"下周"、"月底")或没给时刻 → 尽量推断，推断不了时 understood=false 且 question 写追问(例如"是几号几点呢?")
- 与日程安排完全无关的话 → understood=false, question=null
- durationMin 仅在用户说了时长("两个小时")时填
```

- 调用 `genericCompletion([{role:'system',content:prompt}], {temperature:0.1, maxTokens:400})`；JSON 抢救同 C5。
- **本地校验**（不过全拒绝并返回 question 让用户补）：`dayjs(start,'YYYY-MM-DD HH:mm',true).isValid()`；start 不得早于当前时刻；不得晚于 1 年后；durationMin ∈ (0,1440]。合法则物化 draft（含 reminders）返回。

## F3. Excel 拆解（services/schedule/excel.js）

`parseExcel(path) → { sheetNames, rows }`：exceljs 读首个工作表（或行数最多的表），表头行 + 数据行 → `{cols:[...], rows:[[...]]}`，截取 ≤200 行 × ≤8 列，单元格文本 ≤50 字。

`decompose(rowsText) → { tasks:[...] }`：prompt（`prompts.scheduleDecompose`）全文：

```
你是项目计划拆解器。只输出 JSON，不要有任何其他文字。
当前时间：{nowText()}

用户上传了一份项目管理表（表头+行，以 | 分隔）：
{rowsText}

把其中的计划拆解为带时间节点的任务列表，输出：
{"tasks":[{"title":"≤16字","notes":"≤40字的补充说明或空串",
  "expectedStart":"YYYY-MM-DD HH:mm 或 null",
  "deadline":"YYYY-MM-DD HH:mm 或 null",
  "remindPreset":"start/deadline/none"}]}

规则：
- 表内的相对时间(第3天/D+3/下周/月底/9月20日)全部换算为绝对时间；没写时间的任务两个时间字段填 null
- 有 deadline 的任务 remindPreset="deadline"；只有开始时间用 "start"；都没有用 "none"
- 琐碎/汇总行合并或跳过，最多 30 条，按时间升序
- 表格与任务无关(通讯录/成绩单等) → tasks 为空数组
```

temperature 0.1 / maxTokens 3000。每条 task 过 F2 同款校验，非法行丢弃并在预览中灰显「(解析失败已跳过)」。

## F4. 调度器（services/schedule/scheduler.js）

```js
start()   // app ready 时启动：loadEvents() → catchUp() → setInterval(tick, 30_000)
tick()    // now = dayjs()
  // 1. 待触发：event.status==pending，reminder.status==pending，reminder.at <= now
  //    → 立刻 status='fired'; firedAt=now; save()   【先持久化再广播，防崩溃重发】
  //    → fire(event, reminder)
  // 2. 小睡唤醒：reminder.snoozedTo && now >= snoozedTo && snooze 唤醒未发
  //    → snoozedTo=null; snoozeCount++; 再走一次 fire（气泡标记"第N次提醒"）
  // 3. 过期未触发：at < now - catchupHours(默认24h) 且 status==pending → status='missed'
fire(e, r)
  // ① 宠物：broadcastEmotion('surprised', {source:'schedule', revertMs:8000})
  //         + pet:bubble {kind:'schedule-card', ...} → 宠物窗弹提醒卡
  // ② 系统通知：settings.schedule.systemNotification 时 new Notification({
  //      title: `📅 ${e.title}`, body: `${r.label}｜${相对时间描述(如"1小时后开始"/"即将截止")}` })
  //    notification.click → openWindow('schedule')；appUserModelId 已在 A 设置
  // ③ 提示音：settings.schedule.sound 时宠物窗播放 resources/ding.wav（HTMLAudioElement，音量0.6）
catchUp() // 启动时：at < now 且 status==pending：
  //   now - at <= 24h → 打包成 {event,reminder}[] 广播 schedule:catchup → 日程页红点 + 宠物气泡
  //     「有 N 个错过的提醒：①xxx ②yyy」(≤3条，更多显示"等")，这些 reminder 标 fired(firedAt=now)
  //   更早 → status='missed'
```

用户动作（IPC）：`schedule:snooze {reminderId}` → `snoozedTo = now + settings.schedule.snoozeMin`；`schedule:dismiss {reminderId}` → 仅关卡片（已 fired，无操作）；`schedule:done {eventId}` → status='done', doneAt=now，余下 pending reminders 全部 cancelled。

**宠物提醒卡**（bubble.js 扩展 kind:'schedule-card'）：标题 + 时间描述 + 四按钮 `[知道了] [稍后10分钟] [已完成] [查看]`，不自动消失（停留至点击，但同屏最多 1 张，后来的排队）。

## F5. 日程页（src/renderer/schedule/）

布局自上而下：
1. **速添栏**：大输入框 + 「➕ 添加」+ 示例占位文案「试试：明天晚上18点我要跟女朋友约会」。提交 → `schedule:parse` → `understood` → 弹确认卡；`question` → 输入框下方黄条显示追问、不清空用户输入。
2. **导入区**：「📄 导入 Excel 项目表」按钮 + 拖拽区 → `schedule:excel-parse` → 预览模态（可编辑表格：每行 title/开始/截止/提醒预设下拉，行可删，顶部可全选跳过）→「导入 N 条」→ `schedule:excel-import`。
3. **7 天条**：今起 7 个日期 chip，显示当天事件数点；点击过滤下方列表。
4. **列表**：分组 今天 / 明天 / 本周 / 更晚 / 已完成(折叠) / 已取消(折叠)。卡片：时间（或截止）+ 标题 + kind/source 徽章 + 已物化提醒 chips（可删/可手动补加「+自定义提前量」）+ 操作 编辑/完成/删除。编辑 = 行内展开表单（与确认卡同组件）。
5. **手动添加**：速添栏右侧「表单添加」→ 空白确认卡。

**确认卡组件**（速添/表单/编辑共用）：字段 title/kind(下拉)/start(日期+时间输入)/durationMin/deadline/notes + 提醒预览 chips（由 preset 物化，可增删改分钟数）→「保存」→ `schedule:add`（服务端再校验一次时间合法性）。

**红点与补报**：订阅 `schedule:catchup` → 顶部黄条「⏰ 有 N 条错过的提醒」点击展开列表（可逐条标记完成/忽略）。
